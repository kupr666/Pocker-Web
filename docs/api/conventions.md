# Общие правила API

Статус: техническое предложение v0.1. Согласованные продуктовые правила
перечислены в [product.md](../product.md).

## Транспорты

Согласовано: HTTP/JSON для аккаунтов, профилей, каталога, настроек и истории;
WebSocket для входа за стол, посадки, игровых команд и событий;
gRPC для внутренних вызовов. Клиент обращается только к Gateway.

## Идентификаторы, время, числа

- Идентификаторы — непрозрачные строки; клиент не разбирает их структуру.
- `user_id` неизменяем, `username` уникален с учётом регистра.
- Все моменты времени в JSON — RFC 3339 UTC; в protobuf — Timestamp.
- Фишки — целое неотрицательное число, не float и не денежная валюта MVP.
- В JSON `int64`/`uint64` (фишки, версии, последовательности) кодируются
  десятичными строками, чтобы браузер не терял точность.
- Номер места — целое от 1 до `max_seats`.
- Неизвестное значение enum отвергается при записи; при чтении клиент
  должен уметь показать неизвестное состояние без падения.

## Авторизация

- Весь продукт требует входа, кроме регистрации, входа и обновления сессии
  по отдельному действующему refresh credential.
- Публичный профиль не содержит email, пароля, токенов и списка сессий.
- Gateway определяет пользователя по сессии. Поля actor/context в gRPC
  заполняются доверенным сервером, а не копируются из клиентских заголовков.
- Каждый сервис проверяет права на свою операцию; сетевое расположение
  само по себе не делает caller доверенным.
- Конкретный механизм доверия между сервисами пока не выбран.
- Черновик HTTP использует Bearer access token; refresh token — в теле
  запроса. Это предложение для схем, а не утверждённая политика хранения
  токенов браузером. Сроки, ротация и выбор cookie требуют решения до реализации.
- Черновик WebSocket передаёт access token первым сообщением, не в URL.
- После отзыва сессии связанный допуск и активный игровой поток должны
  перестать принимать действия/отдавать закрытые данные. Механизм отзыва открыт.

## Ошибки

HTTP-ответ:

```json
{"error":{"code":"SEAT_TAKEN","message":"Seat is occupied","request_id":"req-123","retryable":false}}
```

WebSocket использует тот же объект внутри `command.error`.
В gRPC — стандартный status и `google.rpc.ErrorInfo` с машинным reason;
схема ErrorInfo не генерируется заново в этом репозитории.

| gRPC | HTTP | Примеры reason |
| --- | --- | --- |
| INVALID_ARGUMENT | 400 | VALIDATION_FAILED |
| UNAUTHENTICATED | 401 | SESSION_EXPIRED |
| PERMISSION_DENIED | 403 | ACCESS_DENIED, OWNER_REQUIRED |
| NOT_FOUND | 404 | TABLE_NOT_FOUND, HAND_NOT_FOUND |
| ALREADY_EXISTS / ABORTED | 409 | USERNAME_TAKEN, SEAT_TAKEN, STALE_VERSION, IDEMPOTENCY_CONFLICT |
| FAILED_PRECONDITION | 409 | ACTIVE_WINDOW_EXISTS, SETTINGS_LOCKED, HAND_IN_PROGRESS, REBUY_NOT_ALLOWED |
| RESOURCE_EXHAUSTED | 429 | RATE_LIMITED |
| UNAVAILABLE | 503 | SERVICE_UNAVAILABLE |
| DEADLINE_EXCEEDED | 504 | UPSTREAM_TIMEOUT |
| INTERNAL / UNKNOWN | 500 | INTERNAL_ERROR |

Для недоступной скрытой сущности возвращается NOT_FOUND, чтобы не раскрывать
её существование. Внешние ошибки не содержат внутренних адресов и stack trace.
Нельзя раскрывать чужие карты даже в ошибках, логах или трассировках.

## Повторы и версии

- HTTP-операции с побочными эффектами требуют `Idempotency-Key`.
- WS-команды используют `request_id`; повторы heartbeat не требуют хранения результата.
- Ключ дедупликации включает пользователя, операцию и request_id.
- Повтор того же ключа и того же payload возвращает исходный результат;
  тот же ключ с другим payload — IDEMPOTENCY_CONFLICT.
- Для неавторизованной регистрации ключ связывается с отпечатком запроса;
  повтор должен подтвердить те же регистрационные credentials, а не только знать ключ.
- Request id не является разрешением на чтение чужого результата.
- Срок хранения ключей — открытое решение. Проверка hand_id/версии обязательна
  независимо от того, сохранился ли результат дедупликации.
- Изменения правил требуют `expected_revision`; игровые действия —
  `hand_id` и `expected_version` текущего снимка.
- Game сериализует изменение состояния стола. Проверка версии и применение
  команды выполняются как единая операция.
- Версия/sequence после перезапуска не должна повторять значения старой эпохи.

## Пагинация

Предложение: `page_size` по умолчанию 20, максимум 100; `page_token` непрозрачен
и связан с фильтрами и пользователем. Возвращается `next_page_token`, пустая
строка означает конец. Общий total не обязателен.

Каталог: `(created_at DESC, table_id DESC)`.
История: `(finished_at DESC, hand_id DESC)`. При первом запросе фиксируется
верхняя граница выборки. Gateway объединяет Game и Archive, устраняя дубликаты
по hand_id. Курсор опирается на границу ключа, а не только offset источников:
перенос записи не должен заставлять пропускать её. При сбое одного источника
полная история возвращает ошибку, а не незаметно неполную страницу.

## Будущая проверка схем

Сейчас оформлена только документация; команды ниже предназначены для этапа создания схем.

- Protobuf: `task proto`, затем `go test ./...`.
- OpenAPI: валидатор OpenAPI 3.1.
- WebSocket: JSON Schema Draft 2020-12.
- Схемы проверяют форму, но не заменяют проверки прав, лимитов и состояния игры.

Справочные спецификации: [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0),
[protobuf proto3](https://protobuf.dev/programming-guides/proto3/).
