# API: первый черновик

Статус: предложение для обсуждения, не утверждённый контракт.
Продуктовые решения: [product.md](../product.md).
Границы сервисов: [architecture.md](../architecture.md).
Чат не входит в MVP.

Имена методов и полей ниже предварительные. После согласования сценариев
внешний HTTP API будет описан в OpenAPI, внутренний — в protobuf.
Незавершённая заготовка `api/proto/auth/auth.proto` этим документом не изменяется.

## Предлагаемые транспорты

- HTTP/JSON: аккаунты, профили, каталог и настройки столов, история.
- WebSocket: активное окно, вход за стол, игровые команды и события.
- gRPC: внутренние вызовы сервисов; стрим событий от Game к Gateway.

Сервер определяет пользователя из проверенной сессии.
Клиент не может выбрать действующего пользователя через произвольный `user_id`.
Публичный и защищённый паролем стол видимы только авторизованным пользователям.
Скрытый стол не попадает в общий каталог.

## Внешний HTTP API Gateway

Префикс: `/api/v1`. Авторизация требуется везде, кроме регистрации,
входа и обновления сессии (для обновления требуется действующий refresh credential).

| Метод и путь | Действие | Внутренний сервис |
| --- | --- | --- |
| POST /auth/register | Email, пароль, username, display_name → аккаунт, профиль, сессия | Auth → User |
| POST /auth/login | Email и пароль → сессия | Auth |
| POST /auth/refresh | Обновить сессию | Auth |
| POST /auth/logout | Завершить текущую сессию | Auth |
| POST /auth/logout-all | Завершить все сессии пользователя | Auth |
| GET /users/me | Собственный профиль | User |
| PATCH /users/me | Изменить display_name | User |
| GET /users/{user_id} | Публичный профиль без email и данных авторизации | User |
| GET /tables | Список видимых столов: поиск по названию, фильтры свободных мест, отсутствия пароля и не начавшейся игры | Lobby |
| POST /tables | Создать стол | Lobby → Game |
| GET /tables/{table_id} | Метаданные доступного стола, без состояния скрытых карт | Lobby |
| PATCH /tables/{table_id} | Изменить правила до начала первой раздачи | Lobby → Game |
| POST /tables/{table_id}/close | Запретить входы, завершить текущую раздачу, закрыть стол | Lobby → Game |
| POST /tables/{table_id}/owner | Передать роль владельца участнику | Lobby |
| POST /tables/{table_id}/invitation | Выпустить или заменить единственное действующее приглашение | Lobby |
| DELETE /tables/{table_id}/invitation | Отозвать действующее приглашение | Lobby |
| GET /users/me/hands | Единая история собственных раздач | Game + Archive |
| GET /hands/{hand_id} | Детали раздачи с проверкой участия и фильтрацией карт | Game или Archive |

Согласовано: у скрытого стола одно многоразовое приглашение (ссылка и код),
действующее до закрытия стола или отзыва. Владелец может заменить его;
предыдущее сразу теряет силу для новых входов, но вошедшие участники остаются.
Приглашение требует авторизации, допускает наблюдение и не резервирует место.
Восстановление действующего участия после обрыва связи не является новым входом.
Первичная выдача приглашения при создании скрытого стола ещё требует детализации.
Согласованный порядок: вход за стол как наблюдатель → выбор свободного места →
явное подтверждение готовности. Создатель проходит тот же путь;
роль владельца не занимает место. Создание и просмотр стола не начисляют фишки.
Первая успешная посадка выдаёт стартовый стек, повторная следует настройкам стола.

## Каталог столов

Согласованные поля элемента списка: `table_id`, название, владелец,
занятые/все места, малый и большой блайнды, стартовый стек,
наличие пароля и состояние игры. Название задаётся владельцем и не уникально.

Предлагаемые query-параметры `GET /tables`:

- `query`: поиск по названию;
- `has_available_seats`: только столы со свободными местами;
- `without_password`: только столы без пароля;
- `not_started`: только столы, где первая раздача ещё не началась;
- `page_size`, `page_token`: параметры пагинации, точная схема ещё не утверждена.

Сортировка по умолчанию — новые столы первыми. Для устойчивой пагинации
предлагается порядок `created_at DESC, table_id DESC`.
Скрытые столы исключаются сервером независимо от поисковых параметров.
Поиск доступен только авторизованным пользователям.
Число свободных мест в каталоге носит информационный характер:
окончательно возможность посадки проверяется в Game.
Поиск по регистру и ограничения длины названия ещё предстоит определить.

## Автоматическое закрытие пустого стола

Стол пуст, если нет занятых игровых мест. Наблюдатели и владелец без места
не препятствуют закрытию. Таймер 10 минут начинается при создании стола
или освобождении последнего места. Посадка отменяет его.
Освобождение последнего места запускает новый отсчёт.

Game — источник сведений о местах. Процесс автоматического закрытия должен
согласовываться с посадкой: устаревший таймер не может закрыть стол, в котором
уже занято место. Конкретный механизм согласования Lobby/Game пока не выбран.
После закрытия Gateway доставляет наблюдателям событие `table.closed`.
История раздач остаётся доступной участникам после закрытия стола.

## Значения настроек стола по умолчанию

Согласованы: публичный доступ, 6 мест, стартовый стек 1 000,
блайнды 5/10, время хода 30 секунд, сохранение стека при повторном входе,
повторная выдача по запросу без одобрения владельца, лимит 3 выдачи
на игрока за всё время существования стола.

Пауза между раздачами фиксирована: 5 секунд. Она не является параметром
CreateTable/UpdateTable в MVP. Остальные указанные настройки можно изменять
только до начала первой раздачи. Сервер должен применять одинаковые значения
по умолчанию для всех способов создания стола.
Допустимые диапазоны стека и блайндов ещё предстоит определить.

## Активное окно и WebSocket

Предлагаемый адрес: `/api/v1/play`. Способ авторизации соединения пока не выбран.

После проверки сессии сервер пытается атомарно получить допуск активного окна.
При уже занятом допуске второе окно получает `ACTIVE_WINDOW_EXISTS` и закрывается.
Передача управления по запросу нового окна не поддерживается.
Heartbeat продлевает допуск; 30 секунд без подтверждений освобождают его.
Устаревший допуск не позволяет отправлять команды или получать события.

Предлагаемая оболочка команды:

- `request_id`: идентификатор для сопоставления ответа и защиты от повторов;
- `type`: вид команды;
- `table_id`: целевой стол, если применимо;
- `payload`: данные команды.

Идентификатор допуска привязан сервером к соединению и сессии.
Game получает проверенные данные пользователя и допуска от Gateway.
Идемпотентность проверяется с учётом пользователя и типа операции;
тот же идентификатор с другим содержимым должен возвращать конфликт.
Срок хранения результатов повторов ещё предстоит определить.

| Команда | Назначение |
| --- | --- |
| heartbeat | Подтвердить активность окна |
| table.enter | Проверить пароль/приглашение и открыть стол как наблюдатель |
| table.leave | Покинуть стол; для игрока применить правила fold/all-in |
| seat.take | Занять место; во время раздачи ждать следующую |
| player.ready | Подтвердить готовность или возвращение из sit-out; готовность сохраняется между раздачами |
| player.sit_out | Во время участия в раздаче — запросить sit-out после её окончания без fold; между раздачами — включить сразу |
| table.start | Владельцу запустить первую раздачу |
| game.act | Fold, check, call, raise, all-in с hand_id и ожидаемой версией |
| chips.request | При нулевом стеке между раздачами запросить восстановление стартового стека с проверкой режима и лимита |
| chips.decide | Владельцу одобрить или отклонить запрос, если требуется |

События: результат команды, персональный снимок стола, начало/завершение/отмена
раздачи, изменение места/готовности/владельца, закрытие стола и отзыв допуска.
Снимок содержит версию, идентификатор раздачи, дедлайн хода, общие данные
и только те карты, которые вправе видеть получатель.
После переподключения выдаётся актуальный снимок; перечень событий для
воспроизведения и механизм обнаружения пропусков ещё предстоит определить.

### Допуск по стеку

Положительный стек допускает участие даже при сумме меньше большого блайнда.
Недостаток средств для обязательной ставки приводит к all-in на доступную сумму.
Нулевой стек исключает участие в новой раздаче и переводит игрока в sit-out
с общим пятиминутным таймером освобождения места. Повторная выдача выполняется
по запросу, без автоматического пополнения. Режим стола: запрещена,
по запросу игрока или с одобрением владельца. Лимит считается по пользователю
за всё время существования стола, не сбрасывается при выходе и учитывает
восстановление стартового стека при повторном входе. Общие условия выдачи,
включая нулевой стек, действуют и при повторном входе.

## Внутренние gRPC API

Это перечень обязанностей методов; сообщения и коды ошибок ещё не окончательные.

| Сервис | Предлагаемые методы |
| --- | --- |
| Auth | Register, Login, RefreshSession, Logout, LogoutAll; проверка/отзыв сессий — механизм уточняется |
| User | CreateProfile (внутренний), GetProfile, BatchGetProfiles, UpdateDisplayName |
| Lobby | ListTables, CreateTable, GetTable, UpdateTable, CloseTable, TransferOwnership, RotateInvitation, RevokeInvitation, EnterTable, LeaveTable |
| Lobby: допуск | AcquireWindow, RenewWindow, ReleaseWindow; проверка актуальности допуска |
| Game | CreateTableRuntime, UpdateTableRules, RequestCloseTable, GetSnapshot, SubscribeTable, TakeSeat, SetReady, RequestSitOut, StartTable, ApplyAction, LeaveTable, RequestChips, DecideChips |
| Game: история | ListRecentHands, GetRecentHand |
| Archive | StoreHand (внутренний и идемпотентный), ListHands, GetHand |

Внутренние административные методы недоступны напрямую браузеру.
Прикладные сервисы проверяют права на свои операции; доверенные сведения
о пользователе не должны приниматься от непроверенного отправителя.
Создание профиля доступно только процессу регистрации, запись архива — процессу переноса.
Конкретный способ аутентификации сервисов пока не выбран.

## Согласованность и отказы

- Регистрация Auth/User требует восстановления после частичного сбоя.
- Создание и изменение стола Lobby/Game требуют определённого порядка
  подтверждений; нельзя объявить стол готовым до готовности Game.
- Начало первой раздачи и изменение правил должны взаимно исключаться:
  проверка только во внешнем HTTP-обработчике недостаточна.
- Допуск окна не заменяет ограничения участия: освобождение допуска
  не разрешает повторную посадку до завершения раздачи после явного выхода.
- Game последовательно применяет действия стола и отклоняет устаревшие
  действия по hand_id/версии состояния.
- Game подтверждает итог раздачи после надёжной фиксации результата.
- Archive получает раздачи старше 24 часов. До подтверждения надёжной записи
  Game сохраняет копию; повторная отправка по hand_id не создаёт дубликат.
- Архивная история в MVP не удаляется автоматически.
- История объединяет оба источника с устойчивым порядком и устранением
  дубликатов. Возраст записи сам по себе не определяет её местонахождение.

## Решения перед фиксацией схем

1. Подтвердить разделение HTTP/WebSocket и направление внутренних вызовов.
2. Определить возврат к готовности после выдачи и судьбу ожидающего одобрения запроса при выходе.
3. Определить числовые ограничения стека и блайндов.
4. Утвердить пагинацию и правила поиска; определить первичную выдачу приглашения.
5. Выбрать сессии, отзыв доступа, авторизацию соединений и внутренних вызовов.
6. Описать форматы ошибок, идемпотентность, версии и курсорную пагинацию.
7. Зафиксировать OpenAPI/protobuf и проверки контрактов.
