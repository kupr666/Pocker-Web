# Сценарии взаимодействия сервисов

Статус: проект. Продуктовые исходы согласованы; порядок внутренних шагов
предложен для обсуждения, конкретные транзакции и хранилища ещё не выбраны.

## Регистрация

Клиент → Gateway → Auth: email, password, username, display_name.
Auth выделяет user_id и создаёт профиль через User.
После готовности аккаунта и профиля возвращает успешный ответ и сессию.
Повтор не создаёт дубль. При частичном сбое операция остаётся восстанавливаемой,
а не объявляется успешной с отсутствующим профилем.

## Создание стола

Gateway → Lobby: параметры и request_id.
Lobby сохраняет предварительные метаданные, создаёт runtime в Game,
затем публикует готовый стол. Создатель не занимает место автоматически.
Создание скрытого стола может сразу выдавать приглашение — это предложение,
а не окончательно согласованный момент выдачи.

## Вход и посадка

1. Gateway проверяет сессию и получает у Lobby эксклюзивный допуск окна.
2. Lobby проверяет режим доступа и отсутствие другого активного стола.
3. Пользователь входит наблюдателем, Game отдаёт персональный снимок.
4. Пользователь выбирает место. Game атомарно проверяет его доступность.
5. Первая посадка выдаёт стартовый стек; повторная следует правилам стола.
6. Пользователь нажимает «Готов». Владелец запускает первую раздачу.

Список мест в каталоге информационный: окончательную проверку выполняет Game.

## Игровое действие

Клиент → Gateway: request_id, hand_id, expected_version, action.
Gateway проверяет сессию/допуск, Game проверяет очередь, версию и правила,
применяет действие один раз и публикует персонализированные снимки.
Персонализация выполняется сервером до отправки.

## Явный выход

Gateway/Lobby согласуют выход с Game. Обычная рука сбрасывается,
all-in доигрывается. Место и запрет повторной посадки удерживаются до конца
раздачи; затем фиксируется итоговый стек, освобождается место и допуск стола.
Механизм межсервисного уведомления об окончании ожидания ещё предстоит выбрать.

## Потеря связи

Таймер хода продолжает идти. По таймауту check или fold, затем sit-out.
Через 30 секунд без подтверждений освобождается окно, но не место.
Пять минут sit-out освобождают место, при необходимости после конца раздачи.
Старое соединение после утраты допуска не может продолжать действия.

## Закрытие

Ручное закрытие запрещает новые входы, завершает текущую раздачу и закрывает стол.
Автоматическое закрытие возможно после 10 минут без занятых мест.
Game атомарно согласует проверку пустоты с посадкой; устаревший таймер
не закрывает стол с вновь занятым местом. Зрители получают уведомление.

## Восстановление Game

Завершённые зафиксированные раздачи сохраняются. Незавершённая отменяется,
стеки возвращаются к значениям до блайндов один раз. Изменения состава стола
нельзя потерять при восстановлении. Порядок повторного старта ещё открыт.

## Архивация и история

Через 24 часа после завершения/отмены Game передаёт запись в Archive.
Ack выдаётся после надёжной записи; только затем Game удаляет свою копию.
Повтор определяется по hand_id, несовпадающее содержимое — конфликт.
Gateway читает историю из обоих источников, устраняет дубликаты и обеспечивает
единый порядок. Если один источник недоступен, полная история не имитируется
частичной выдачей. Доступ есть только у участников соответствующей раздачи.
