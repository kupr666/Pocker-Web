# Lobby

Статус: проект документации API v0.1. Схемы и реализация пока не созданы.

## Ответственность и данные

Владеет каталогом, метаданными, правилами доступа, приглашениями, владельцем
и централизованным допуском одного игрового окна/стола на пользователя.
Game — источник мест, стеков, раздач и факта первой раздачи.

Сущности: Table, TableRules, Invitation, WindowLease, TableAdmission.
Пароль стола хранится как хеш. Секрет приглашения не входит в каталог.

## Столы

Публичный, с паролем или скрытый по приглашению. Каталог только после входа;
фильтры: свободные места, без пароля, игра не началась; поиск по названию.
Новые столы первыми. Названия не уникальны.

Правила изменяются только до первой раздачи; Game должен атомарно исключать
конкурентный старт со старой конфигурацией. Полный набор defaults — в product.md.
Создание не сажает владельца. Вход — наблюдение, затем отдельная посадка.

## API

Ниже — предлагаемый API. Protobuf-контракт пока не оформлен.

- ListTables, GetTable, CreateTable, UpdateTable, CloseTable.
- TransferOwnership.
- RotateInvitation, RevokeInvitation: одно многоразовое приглашение,
  действует до закрытия/отзыва; замена не выгоняет участников.
- AcquireWindow, RenewWindow, ValidateWindow, ReleaseWindow.
- EnterTable, LeaveTable: управляют допуском; выход согласуется с Game.

## Окно и участие

Аренда эксклюзивна по user_id, связана с session_id и connection_id.
30 секунд без подтверждения освобождают блокировку. Новый connection_id
не вытесняет старый. Аренда содержит монотонный fence: устаревшее соединение
не может действовать или получать события после выдачи нового допуска.
Проверка допуска должна обеспечиваться перед выполнением, а не только при входе.

Истечение окна не освобождает место и не списывает/начисляет фишки.
Выход в текущей раздаче удерживает ограничение посадки до её завершения,
даже если аренда окна уже истекла.

## Владение и закрытие

Владелец передаёт роль участнику; при явном выходе роль получает самый ранний
оставшийся участник. Отключение само по себе роль не меняет.
Пустой стол без занятых мест закрывается через 10 минут; зрители его не удерживают.
Ручное закрытие запрещает входы и ждёт конца раздачи. История сохраняется.
Game должен сериализовать проверку пустоты/закрытие с посадкой.

## Отказы

Создание: состояние preparing до подтверждения Game. Частичный сбой
должен допускать повтор по тому же table_id, без дубликатов.
Изменение: revision и атомарная проверка Game относительно первого старта.
Каталог может быть проекцией; его число мест не гарантирует успешную посадку.
События lifecycle несут revision и применяются идемпотентно.

## Открытые вопросы

Доступ наблюдателей к владению, отсутствие преемника, несколько создаваемых
столов, механизм аренды/fencing, синхронизация каталога: реестр решений.
