# Gateway

Статус: проект документации API v0.1. Схемы и реализация пока не созданы.

## Ответственность

Единственная внешняя точка входа: HTTP/JSON и WebSocket. Проверяет сессию,
связывает соединение с пользователем, вызывает внутренние gRPC API,
преобразует ошибки и возвращает данные в разрешённой форме.

Gateway не хранит пароли, балансы или истинное состояние раздачи и не решает,
разрешена ли ставка: это проверяет Game. Он не доверяет клиентскому user_id.

## Контракты

## Состояние и зависимости

Локально: активные соединения, ограниченные очереди отправки, связь
connection → user/session/window. Авторитетный допуск окна хранит Lobby.
Зависимости: Auth, User, Lobby, Game, Archive.

Для истории Gateway объединяет Game/Archive с дедупликацией и проверкой
полноты страницы. Конкретные gRPC-соединения переиспользуются.

## Сценарии и отказы

- HTTP-запрос получает ограниченный дедлайн; отмена передаётся downstream.
- При WS authenticate проверяется сессия и получается допуск Lobby.
- Второй допуск не вытесняет первый. Клиент не может задавать fencing token.
- Истечение допуска или отзыв сессии прекращают команды и персональные события.
- При разрыве потока возвращается свежий снимок, а не слепой повтор ставок.
- Медленный клиент не создаёт неограниченную очередь: закрытие соединения
  требует восстановления снимка; точные лимиты пока открыты.
- Если один источник истории недоступен, нельзя выдавать неполную историю как полную.

## Проверки перед реализацией

Авторизация всех маршрутов, блокировка второго окна, истечение допуска,
отмена RPC, недопущение утечки карт, сортировка/дедупликация истории,
повтор ставки после потерянного ответа, восстановление после разрыва потока.
