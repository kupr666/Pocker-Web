# WebSocket-протокол: проект

Статус: описание для обсуждения. Машиночитаемой схемы и реализации пока нет.
Согласовано использование WebSocket для игры, HTTP для остальных операций
и gRPC между сервисами. Технические детали ниже — предложения.

## Подключение

Предлагаемый endpoint: `/api/v1/play`.

1. Клиент открывает соединение.
2. Первое сообщение authenticate передаёт access token; токен не помещается в URL.
3. Gateway проверяет сессию и получает у Lobby допуск окна.
4. При занятом допуске возвращает ACTIVE_WINDOW_EXISTS и закрывает второе соединение.
5. При успехе подтверждает авторизацию и сообщает срок аренды.

До авторизации игровые данные недоступны. Предложенные технические значения:
5 секунд на authenticate, heartbeat каждые 10 секунд. Согласованный таймаут
освобождения аренды — 30 секунд без подтверждений.

Новое окно не может вытеснить старое. После утраты допуска старое соединение
не принимает действия и не получает персональные события. Формат токенов,
точный механизм fencing и доставки отзыва ещё требуют решения.

## Оболочка команды

- type — тип команды.
- request_id — идентификатор запроса и ключ защиты от повторов.
- table_id — стол для команд участия.
- payload — данные команды.

Пользователь и действующий допуск устанавливаются Gateway на основании
соединения. Они не берутся из произвольного поля user_id в сообщении клиента.

| Команда | Payload | Результат |
| --- | --- | --- |
| authenticate | access_token | Допуск окна или ошибка |
| heartbeat | Пустой | Новый срок аренды |
| table.enter | password или invitation_code при необходимости | Вход как наблюдатель и персональный снимок |
| seat.take | seat | Занятое место; во время раздачи ожидание следующей |
| player.ready | Пустой | Готовность, сохраняющаяся между раздачами |
| player.sit_out | Пустой | Sit-out сейчас или после текущей раздачи |
| table.start | Пустой | Первая раздача, только для владельца |
| game.act | hand_id, expected_version, action, raise_to только для raise | Подтверждение действия и новая версия |
| table.leave | Пустой | Выход; при активной раздаче отложенное освобождение места |
| chips.request | Пустой | Выдача или запрос на одобрение |
| chips.decide | grant_id, approve | Решение владельца по запросу |

`raise_to` — общий вклад игрока в текущем круге торговли после повышения,
а не добавляемая сумма. Call/check/fold не содержат произвольную сумму ставки.

## Ответы и события

Ответ содержит request_id. Ошибка содержит code, message, retryable.
События стола содержат table_id, sequence, время и персонализированную нагрузку.

- command.result / command.error — результат конкретной команды.
- table.snapshot — полное актуальное состояние для получателя.
- table.updated — изменение публичных метаданных/владельца.
- hand.ended — завершение или отмена раздачи.
- chips.updated — изменение запроса выдачи, только уполномоченным получателям.
- table.closed — закрытие стола.
- window.revoked — прекращение допуска.

Снимок содержит места, состояния игроков, стеки, ставки, банки, общие карты,
текущую раздачу, версию, дедлайн хода, доступные действия получателя и серверное
время. Карманные карты передаются только владельцу или после публичного раскрытия.

## Переподключение

После восстановления клиент получает новый актуальный снимок. Нельзя повторять
последнюю ставку с новым request_id: старый запрос мог уже выполниться.
Повтор с исходным request_id должен возвращать исходный результат;
устаревшие hand_id/версия не разрешают новое действие.

Переподключение не начисляет фишки и не освобождает место. Пока прежняя аренда
не истекла, второе соединение не получает допуск. Удобное восстановление
после перезагрузки страницы требует отдельного технического решения.

## Отказы и ограничения

Потеря соединения не выполняет немедленный fold: продолжает идти таймер.
Явный table.leave выполняет fold, кроме уже находящейся в all-in руки.
При сбое Game незавершённая раздача отменяется по правилам продукта.
Нельзя накапливать неограниченную очередь событий медленному клиенту;
лимиты очереди и кадров нужно определить до реализации.
