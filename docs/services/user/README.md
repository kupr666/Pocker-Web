# User

Статус: проект документации API v0.1. Схемы и реализация пока не созданы.

## Ответственность

Владеет публичным профилем и уникальностью никнейма. Не хранит пароль,
refresh tokens, баланс и состояние игры.

Profile: user_id, username, display_name, created_at.

- user_id неизменяем и приходит из процесса регистрации Auth.
- username: 3–24 символа `[A-Za-z0-9_]`, уникален с учётом регистра,
  не меняется в MVP. `Player` и `player` различны.
- display_name: 1–40 Unicode-символов после trim, может повторяться и изменяться.
- Аватар и прочие настройки отложены.

## API

Ниже — предлагаемый API. Protobuf-контракт пока не оформлен.

| Метод | Доступ и поведение |
| --- | --- |
| CreateProfile | Только Auth; идемпотентно по user_id/request_id; конфликт другого владельца username запрещён |
| GetProfile | Авторизованный запрос публичного профиля по user_id |
| BatchGetProfiles | Доверенные сервисы для отображения участников без N отдельных запросов |
| UpdateDisplayName | Только собственный профиль; username не принимается |

Email не возвращается ни одним методом. Список всех пользователей и поиск
по никнейму в MVP не предлагаются без отдельного продуктового сценария.

## Ошибки и согласованность

Уникальность nickname должна обеспечиваться хранилищем с case-sensitive
сравнением, а не только предварительным SELECT. Неверное имя → INVALID_ARGUMENT,
занятый username → ALREADY_EXISTS, отсутствующий профиль → NOT_FOUND.
Повтор создания user_id с другим содержимым → конфликт, а не перезапись.

## История

История раздач сохраняет имя участника на момент раздачи; смена display_name
не меняет исторические записи и не ломает связь по user_id.
Это предложенная семантика отображения, до реализации может быть уточнена.

## Проверки

Границы длины, Unicode display_name, trim, case-sensitive uniqueness,
конкурентная регистрация, повтор CreateProfile, запрет изменения чужого профиля.
