# Game

Статус: проект документации API v0.1. Схемы и реализация пока не созданы. Старый Game API считается экспериментом.

## Ответственность и данные

Единственный владелец состояния игры: места, готовность, раздачи, карты,
позиция дилера, блайнды, действия, стеки, банки, таймеры, sit-out,
повторные выдачи и недавняя история. Не владеет аккаунтным балансом.

Предлагаемые сущности: TableRuntime, Seat, Hand, Pot, Action,
ChipGrantRequest, PlayerTableStack, FinishedHand.

## Игровые правила MVP

- No-Limit Texas Hold’em, 2–9 мест, фиксированные блайнды.
- Владелец запускает первую раздачу при минимум двух готовых игроках;
  следующие автоматически через 5 секунд, если хватает готовых игроков.
- Посадка во время раздачи даёт участие со следующей.
- Готовность сохраняется между раздачами.
- Таймер 15/30/60 секунд, default 30. Таймаут: check если доступен, иначе fold,
  затем sit-out; обрыв соединения не останавливает таймер.
- Добровольный sit-out во время раздачи отложен до её окончания, без fold.
- После 5 минут sit-out место освобождается, при необходимости после раздачи.
- Явный выход — fold; уже all-in рука доигрывается. До конца раздачи место
  удерживается, новая посадка за любой стол запрещена.
- Положительный малый стек допускается; нехватка блайнда → all-in на доступную сумму.
- Нулевой стек → sit-out. Повторная выдача только по запросу между раздачами,
  при нуле, до стартового стека. Лимиты и одобрение не обходятся повторным входом.

## API

Ниже — предлагаемый API. Новый protobuf-контракт пока не оформлен.

- CreateTableRuntime, UpdateTableRules, RequestCloseTable — только Lobby.
- GetSnapshot, SubscribeTable — персонализированные данные по допуску.
- TakeSeat, SetReady, RequestSitOut, StartTable, ApplyAction, LeaveTable.
- RequestChips, DecideChips — проверяют правила стола и полномочия владельца.
- ListRecentHands, GetRecentHand — только собственная история.

`raise_to` означает общий вклад игрока в текущем круге торговли после повышения,
а не величину добавки. Call/check/fold не принимают произвольную сумму.
Game определяет доступные действия, min/max raise и права на побочные банки.
Снимок предоставляет эти пределы, но сервер повторно проверяет каждое действие.

## Персонализация

Сервер формирует отдельный снимок для каждого получателя: собственные карты
игрока, публичные общие карты и только реально раскрытые чужие карты.
Зритель не получает карманные карты до их раскрытия. Нельзя рассылать полный
снимок и рассчитывать на скрытие интерфейсом. Архив применяет ту же политику.

## Версии и повторы

Выполнение команды последовательно на стол. ApplyAction требует hand_id,
expected_version и request_id. Проверка прав, допуска, версии и применение
атомарны относительно других игровых команд. Ответы после таймаута могут
быть потеряны: повтор не должен повторно списывать фишки.

## Восстановление и архив

До старта надёжно сохранить исходные стеки до блайндов. Итоги раздачи и
признак завершения фиксируются атомарно, затем публикуется результат.
После сбоя незавершённая раздача отменяется; исходные стеки восстанавливаются
один раз. Результаты зафиксированных раздач не откатываются.

Через 24 часа finished/cancelled история передаётся Archive. Удаление локальной
копии только после надёжного ack. История включает side pots, распределения,
последовательность действий и видимость карт, чтобы перенос не менял результат API.

## Проверки перед реализацией

Сохранение суммы фишек с учётом выдач, side pots, частичный блайнд,
минимальный raise, неполный all-in raise, очередность, heads-up,
выход all-in, таймаут, двойная команда, закрытие одновременно с посадкой,
гонка старта и изменения правил, отмена после сбоя, отсутствие утечек карт.

## Открытые вопросы

Хранилище и failover, восстановление готовности после сбоя, границы числовых
значений, судьба ожидающих выдач: реестр решений.
