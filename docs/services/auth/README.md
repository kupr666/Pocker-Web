# Auth

Статус: проект документации API v0.1. Схемы и реализация пока не созданы.

## Ответственность и данные

Владеет email для входа, хешем пароля, состоянием аккаунта, сессиями и
секретами токенов. Не владеет публичным профилем и игровым допуском окна.
С User связывается неизменяемым user_id.

Предлагаемые сущности: Account(user_id, email, password_hash, status, created_at),
Session(session_id, user_id, expires_at, revoked_at, refresh_credential_hash).
Исходные пароли и токены не пишутся в логи и не выдаются через профиль.

## Согласованное поведение

Регистрация: email, пароль, уникальный case-sensitive username, display_name.
После успеха пользователь авторизован. Вход — email + пароль.
Подтверждения email и восстановления пароля в MVP нет.
Несколько сессий аккаунта допустимы; ограничение окна обеспечивает Lobby.
Есть выход из текущей и из всех сессий.

## API

Ниже — предлагаемый API. Protobuf-контракт будет написан отдельно после согласования.

| Метод | Вход | Выход |
| --- | --- | --- |
| Register | request_id, email, password, username, display_name | профиль и новая сессия |
| Login | request_id, email, password | новая сессия |
| RefreshSession | request_id, refresh_token | обновлённая сессия |
| ValidateSession | access_token | user_id, session_id, срок |
| Logout | действующая сессия, request_id | подтверждение |
| LogoutAll | действующая сессия, request_id | подтверждение |

Register/Login/Refresh доступны Gateway; ValidateSession — доверенным сервисам.
Username conflict → ALREADY_EXISTS; неверные credentials → UNAUTHENTICATED.
Ошибка входа не сообщает отдельно, существует ли email.

## Регистрация и частичный сбой

Предложение: Auth выделяет user_id и хранит незавершённую регистрацию,
идемпотентно вызывает User.CreateProfile. Успех и токены доступны только после
создания профиля и активации аккаунта. Повтор не создаёт второй профиль.
Временный сбой требует повторного продолжения операции; постоянный конфликт
никнейма — определённого освобождения/отмены регистрации. Детали ещё открыты.

## Завершение сессии

Отзыв запрещает новые запросы и должен прекращать связанный активный допуск.
Закрытие соединения не выполняет fold автоматически: оно обрабатывается
как потеря связи. Явный игровой выход — отдельная команда table.leave.
Это техническое предложение требует согласования поведения logout при игре.

## Проверки и открытые решения

Проверить повтор регистрации, конфликт username, частичный сбой User,
отзыв всех сессий и повтор refresh. Формат токенов, сроки, ротация,
хранение браузером и скорость отзыва — [открытые решения](../../decisions/open-questions.md).
